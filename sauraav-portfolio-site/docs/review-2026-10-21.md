# Portfolio review — 21 October 2026

Scope: the whole repository (backend, admin panel, public site). Reviewed against four
lenses: SOLID / code quality, admin-panel security, admin-panel UI, and performance on phones
and low-end devices. Items marked **Fixed** were addressed in the accompanying change set;
items marked **Follow-up** need the owner's input or external systems.

## Critical

| # | Area | Finding | Status |
|---|------|---------|--------|
| C1 | Security | Login compared plaintext credentials with `!=` (timing-unsafe, plaintext secret in config, no throttling, no failure logging). | **Fixed** — PBKDF2 hash via `PasswordHasher`, constant-time username check, fixed-window rate limit on login, warning log on failure, session invalidated when the hash changes. |
| C2 | Security | Video upload accepted any file, kept the original filename and saved it under `wwwroot/videos` where it was served as a static file (stored XSS from the site's own origin). | **Fixed** — `IMediaStorage` allow-lists `.mp4/.webm`, checks content type and magic bytes, names files by GUID, enforces a size limit. |
| C3 | Security | An empty name produced the Firebase path `education/`, which overwrote or deleted the whole section. `ModelState` was never checked. | **Fixed** — `PortfolioKey` rejects blank keys; validation runs in `SectionAdminService<T>` and returns 400 with field errors. |
| C4 | Security | `DELETE` endpoints had no antiforgery validation and the client sent no token. | **Fixed** — `[AutoValidateAntiforgeryToken]` on `AdminController`; all admin requests send the header. |
| C5 | Security | Firebase Realtime Database is accessed without credentials, so the database rules must allow anonymous writes. | **Follow-up** — optional `Firebase:ServiceAccountJsonPath` is now supported; the database rules must be changed in the Firebase console (see README). |
| C6 | Admin UI | Editing an entry's name created a duplicate because the key is derived from the name and the original was never deleted. | **Fixed** — the client sends `originalKey`; the service deletes the old key when it changes. |
| C7 | Admin UI | Rows were built with `innerHTML` and JSON inlined into `onclick` attributes: broke on apostrophes and allowed stored XSS. | **Fixed** — DOM built with `createElement`/`textContent`, event delegation on `data-key`. |
| P1 | Performance | 200 DOM stars each updated every frame **and** given a CSS transition; mouse physics ran on touch devices; never paused. | **Fixed** — single canvas, star count scaled to device tier, pauses when hidden, static under `prefers-reduced-motion`. |
| P2 | Performance | `backdrop-filter: blur(10px)` on every card over a repainting fixed background. | **Fixed** — removed on touch/low-end devices; kept only on desktop with hover. |

## Verification status

- The web project compiled with zero warnings (analyzers at `Recommended`, warnings as errors) after
  the backend refactor. The in-memory store, security-header tweak, admin/public views, scripts,
  stylesheet and the new test project were written afterwards and have **not** been compiled or run,
  at the owner's request. First step after review: `dotnet build` then `dotnet test`, then open the
  public page on a phone-width viewport and the admin panel against the in-memory store.

## Suggestions

- Sanitised keys can collide (`a.b` and `a/b`); consider generated ids with a display name.
- Trim or subset `Gendy.otf` (128 KB) to WOFF2 once a font tool is available.
- `AllowedHosts` should be set to the real domain at deployment time.
- Add a `.env`/user-secrets example for the new `Admin:PasswordHash` key (documented in README).

## Strengths

- Interfaces and DI were already in place, which made the refactor mechanical.
- `LoggerMessage` delegates, analyzers at `Recommended`, and warnings-as-errors were already on.
- The public page was server-rendered, so no client data-fetch had to be replaced.
